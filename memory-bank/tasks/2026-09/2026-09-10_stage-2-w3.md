## 2. Layering proof

- **SSH connection panel:** the bootstrap's setup sheet (`AddServerView`), the add/edit sheets and
  the password prompt are wrapped in `GlassLayeredPanel(cornerRadius: 0)`.
- **Terminal window chrome, visionOS:** `TerminalWindowView.terminalSurface` uses
  `GlassLayeredWindow(showTitle:showControls:)` (ornaments + the shared backdrop) instead of
  `GlassNativeWindowFrame` + its own global backdrop. The canvas keeps theme-colour painting and
  now adds its own `GlassCanvasBackdrop` only for a per-session override (`sessionOverrideBlur`).
- **macOS title bar:** `MacTerminalWindowPolicy.apply` calls `GlassWindowLayerPolicy.apply(window,
  state:)` (the family sequence plus title-bar material alpha following frost); the overview still
  swaps the material style. `MacTerminalWindowReader` reads the state from the environment.
- **State:** `SettingsManager.glassFrost / windowOpacity / blurBackground` are computed over
  `GlassLayerStore` (`layers`, injected by `GlassTerminalRuntime(layers:)` from the app's one
  store; a same-suite store without legacy suites for tests/previews). The three legacy keys are
  no longer written; glas.sh's keys are migrated **on load**, once, and consumed
  (`migrateLegacyAppearanceIfNeeded`). Every terminal scene injects `.glassLayers(runtime.layers)`.
- Verified by compile and unit tests. **Not run:** a running-window check of frost/opacity on the
  terminal window and the connection panel (integration pass).

## 3. Settings

- `SettingsView` (the terminal's own root, 65 lines) and `AppearanceSettingsView` (75 lines)
  deleted. The canvas-only controls (visionOS interactive glass, tint) moved to Terminal ▸ Canvas
  with a note that opacity/frost/material live in Appearance.
- `GlassTerminalSettingsPages.all` (public): Connections (glas.sh General), Terminal, Snippets —
  each a `GlassTerminalSettingsPage` with `view(runtime:)`. Needs the shell hook below to appear.
- **User requirement (2026-09-10): choose a file instead of a paste.** `AddSSHKeyView` (used by
  the settings SSH-keys page and by the server form's key step) has "Choose File…": `NSOpenPanel`
  on macOS starting in the real `~/.ssh` with hidden files shown, `.fileImporter` with
  `[.item, .data]` elsewhere. `SSHPrivateKeyImport.read(from:)` reads inside the security scope,
  caps at 64 KiB, classifies through the engine's header probe and reads the OpenSSH container
  (cipher name → passphrase required; comment when unencrypted). The form shows the detected type
  and comment, pre-fills the name from the comment or file name, focuses the passphrase field for
  protected keys, and hands the text to the unchanged `addSSHKey` path. Nothing but view state
  holds the path or contents. Pasted text is classified the same way.

## 4. Shell services — plan (not moved; `GlassShell` was not mine to edit)

- `WindowRecoveryManager` (161 lines) is already generic (window keys "main"/"minimized"; an
  `OpenWindowAction`). Move as-is to `GlassShell`, expose `trackWindowPresence(key:recovery:)`, and
  have the runtime take the shell's instance instead of creating one.
- `ICloudSettingsSyncService` (822 lines) is an envelope/merge/KVS core plus a terminal payload
  (`ICloudPortableTerminalPreferences`, theme records). Split: the core (writer id, envelope,
  deterministic merge, status, retry) to `GlassShell` as `GlassSettingsSync<Payload: Codable>`;
  the terminal payload stays here and registers with it. `SettingsManager` keeps owning the
  application of its own payload. The KVS identifier is already D3's.

## Hooks proposed for `GlassShell` (messaged to the coordinator)

```swift
public protocol GlassCapability: AnyObject {
    // existing members …
    /// Pages the capability adds to the shell's settings surface, after the shell's own.
    var settingsPages: [GlassCapabilitySettingsPage] { get }          // default []
    /// Toolbar entries for the library window (Workgroups, Tailscale, Local Terminal).
    @MainActor @ViewBuilder func libraryToolbarItems() -> AnyView        // default EmptyView
    /// Actions for one service in the host detail (Edit, Details, SFTP, Delete / Set Up…).
    @MainActor @ViewBuilder func serviceDetailActions(service: HostServiceLink, host: HostProfile) -> AnyView
}
public struct GlassCapabilitySettingsPage: Identifiable { id, title, systemImage, makeView: @MainActor () -> AnyView }
```
`GlassShellSettingsView` appends `registry.registeredKinds.flatMap { settingsPages }` to its
`GlassSettingsSections` options; `GlassShellLibraryView` renders `libraryToolbarItems()` in its
toolbar and `serviceDetailActions` next to each service's Connect. `GlassTerminalCapability`
already has the views to return.

## Behaviour changes (listed)

1. Opacity/frost/material writes from the terminal persist immediately to the shared layer state
   (previously on `saveSettings()`); the three legacy keys are no longer written.
2. visionOS: the shared window backdrop is not gaze-interactive; "Interactive glass" applies to a
   session override's canvas backdrop. When theme painting is on, the shell's theme colour paints
   beneath the terminal's — a `GlassLayeredWindow(paintsTheme:)` option in GlassLayers would remove
   the double paint (proposed, not mine to add).
3. Command palette: "Show saved connection" entries removed (shell owns selection).
4. `ServerInfoView` is internal (was private); `ConnectionWorkgroupSelection` internal.

## Phase 2 — hooks wired, shell services moved, theme double-paint removed (2026-09-10)

After the coordinator landed the three hooks in `GlassShell` (commit `7ebe746`):

- **Hooks wired.** `GlassTerminalCapability` returns `settingsPages` (from
  `GlassTerminalSettingsPages.all`), `libraryToolbarItems()` (`GlassTerminalLibraryToolbar`) and
  `serviceDetailActions(service:host:)` (`GlassTerminalServiceActions`). `open(service:host:)` is
  unchanged: the shell passes the owning record and the terminal resolves `ServerConfiguration`
  by `service.endpointID`, which `GlassShellHost.member(owning:)` guarantees.
- **`GlassWindowRecoveryManager`** (`Sources/GlassShell/GlassShellWindowRecovery.swift`): the
  class moved verbatim and made public with `trackWindowPresence(key:recovery:)`; the terminal
  keeps `typealias WindowRecoveryManager` and `TerminalSessionOverride`. The app creates one
  manager, passes it to `GlassTerminalRuntime(layers:windowRecovery:)`, and tracks the library
  window as `"main"` again (glas.sh did at `glas_shApp.swift:162`; W2's entry had dropped it).
- **`GlassSettingsSyncService<Payload>`** (`Sources/GlassShell/GlassShellSettingsSync.swift`,
  568 lines): the status, store-change, key-value-store protocol, ubiquitous store, envelope,
  merge result, error and service moved verbatim from glas.sh's `ICloudSettingsSyncService.swift`
  and made generic over `GlassSettingsSyncPayload` (`validate()`, `converged(with:)` — the one
  payload-specific call, `mergingThemeRecords`, became that requirement). The store key is the
  consumer's (no default in the shell). The terminal keeps its payload types (263 lines, now
  `nonisolated` value types) and typealiases for every glas.sh name, so all call sites and the
  fake store in the tests compile unchanged; two convenience inits supply
  `terminal-settings-envelope-v1`. Six `TerminalTheme`/`TerminalThemeLibrary` constants became
  `nonisolated static let` so the nonisolated payload can read them.
- **`GlassLayeredWindow(paintsTheme:)`** and `GlassLayerResolution.resolve(_:reduceTransparency:
  paintsTheme:)`: a self-painting surface opts out of the layer's theme paint; Reduce
  Transparency still forces opaque. The terminal window passes `paintsTheme: false`, so theme-on
  no longer double-paints (behaviour change 2 in the earlier list is closed). Test added:
  `paintsThemeOptOut`.
- **Defect found and fixed during verification:** my first terminal convenience initializer
  carried the same labels as the shell's designated one, so it forwarded to itself — a stack
  overflow (SIGSEGV in `swiftpm-testing-helper`, first seen in
  `chosenKeyLandsInTheCatalogThroughAddSSHKey`). The conveniences now use shorter label sets.
