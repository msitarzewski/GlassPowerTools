## Root causes

1. **macOS window 728×164** — shell scene had no default size / min frame. Fixed as W3 planned.
2. **Row identifiers concatenated on macOS** — the kit row's `.accessibilityElement(children: .combine)`
   (`../GlassConnectionKit/.../GlassLibraryComponents.swift:139`). An outer `.contain` cannot split a
   combined element, so the shell names the combined element `host-row-<name>` on macOS; the icons'
   labels ("Terminal", "Desktop") are in the row's label, which the consolidation test asserts on macOS.
3. **Appearance toggle rewritten at launch** — `applyICloudSettingsPayload` wrote the three appearance
   values into the shared `GlassLayerStore` on every payload (live since the KVS entitlement). Now
   carried but not applied; legacy migration is the store's alone.
4. **Sheet-on-sheet crash was misattributed.** Bisected with a temporary env-toggled probe (removed):
   `AddSSHKeyView` on its own, in a window, survives a full accessibility snapshot in every variant;
   the server form with **SSH Key** selected and no other window open crashes on any full snapshot
   (SIGSEGV, `AccessibilityNode.accessibilityLabel` ↔ `_NSAccessibilityOverrideValueForAttribute`
   recursion until the stack guard). Cause: the SSH Key row's `LabeledContent` label from
   `requiredFieldLabel` (`.accessibilityElement(children: .ignore)` + `.accessibilityLabel`) over
   content that is a text-and-button stack. Plain-text label fixes it; Password/Host rows keep the
   combined label because their content is one field. The key form is a window on macOS anyway
   (rule 12). The "Key name" field was never found on macOS because the placeholder is neither label
   nor identifier there — hence `ssh-key-name`.
5. **Post-trust reconnect `sessionNotRegistered`** — the alert's Confirm action starts the retry, then
   SwiftUI sets the alert's `isPresented` binding to false; its setter runs the Cancel cleanup
   (`closePendingHostTrustSession`), which unregisters the session before the retry task calls
   `reconnect`. glas.sh has the same code; it only shows when the retry task is scheduled after the
   dismissal. Fix: `takePendingTrustSession` clears the prompt state synchronously before the task.
   `HostTrustRetryTests` proves both orders against `SessionManager.reconnectContext`.
6. **`lastConnected` on open** — replaced by the outcome report; unit-tested.
7. **Element screenshots on macOS** fail ("Image creation failed") when the app's window is on a
   display other than the primary; `UITestCapture` locates the display holding the window through
   `NSScreen`, captures that `XCUIScreen`, and crops to the window frame (own window only).
